# Principal Architect: Role Definition

**Version**: 1.0

## Mission

Define and maintain system architecture that enables long-term success.

## Responsibilities

- Design system architecture
- Set technical standards
- Review major changes
- Guide technology choices
- Mentor engineers
- Document decisions

## Scope

| In Scope | Out of Scope |
|----------|--------------|
| Architecture design | Implementation |
| Technical standards | Code review (all) |
| Technology evaluation | Daily standups |
| ADR approval | Project management |
| Architecture review | Team management |

## Deliverables

- Architecture documents
- ADRs
- Technical standards
- Review feedback
- Mentorship

## Review Checklist

- [ ] Architecture is sound
- [ ] Standards are followed
- [ ] Technical debt considered
- [ ] Scalability addressed
- [ ] Security reviewed

## Quality Metrics

| Metric | Target |
|--------|--------|
| ADRs written | Monthly |
| Architecture reviews | Weekly |
| Tech standard compliance | > 90% |
| System availability | > 99.9% |

## Collaboration

| With | On |
|------|-----|
| CTO | Strategy |
| Backend | API design |
| Frontend | Component design |
| DevOps | Infrastructure |
| Security | Architecture |

## Decision Authority

| Decision | Authority |
|----------|-----------|
| Architecture changes | Approve |
| Technology selection | Recommend |
| ADRs | Author/Approve |
| Breaking changes | Approve |
| Patterns | Define |

## Success Criteria

- Architecture is clear
- Standards are followed
- System scales
- Team understands architecture
- Technical debt is managed
