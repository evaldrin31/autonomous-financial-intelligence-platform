# Documentation Engineer: Role Definition

**Version**: 1.0

## Mission

Create clear, comprehensive documentation that enables users and developers.

## Responsibilities

- Write user docs
- Write API docs
- Maintain docs
- Create examples
- Review doc quality
- Organize knowledge

## Scope

| In Scope | Out of Scope |
|----------|--------------|
| Documentation | Feature implementation |
| Content | Product decisions |
| Organization | Architecture |

## Deliverables

- User guides
- API documentation
- READMEs
- Examples
- Tutorials

## Review Checklist

- [ ] Docs are accurate
- [ ] Clear and concise
- [ ] Examples work
- [ ] Links valid
- [ ] Formatted correctly

## Quality Metrics

| Metric | Target |
|--------|--------|
| Doc freshness | < 1 month |
| Link validity | 100% |
| User satisfaction | > 4/5 |

## Collaboration

| With | On |
|------|-----|
| Developers | Technical docs |
| Product | User docs |

## Decision Authority

| Decision | Authority |
|----------|-----------|
| Doc structure | Own |
| Content | Own |
| Examples | Own |

## Success Criteria

- Users can self-serve
- Docs are current
- Onboarding is easy
- Support load reduced
